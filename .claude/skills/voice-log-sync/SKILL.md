# 音声ログ → 日置プロフィール 反映

## 目的

ChatGPTとの音声会話ログ(PDF出力後にmd化してこのリポジトリにpushされたもの)を、`AI伴走環境/日置プロフィール/`配下の匿名化済みナレッジベースに定期的に反映する作業を型化する。

## 手順

1. **Pull**
   - `git fetch origin <現在のブランチ>` → `git merge --ff-only` でPull
   - コンフリクトが出た場合は自動解決せずユーザーに確認する

2. **新着ログの検出**
   - `AI伴走環境/` 直下(`日置プロフィール/`サブフォルダを除く)にある `.md` ファイルのうち、直前のPullで追加・更新されたものを `git log`/`git diff --stat` で特定する
   - 該当ファイルが見つからなければ、その旨をユーザーに伝えて処理を止める(推測で反映しない)

3. **既存プロフィールの確認**
   - `AI伴走環境/日置プロフィール/00_index.md` で構成を確認
   - 更新対象になりそうな `01`〜`07` の既存ファイルを実際に読み、文体・見出しの粒度・既存の匿名化の言い換えパターン(例:実在の会社名 →「既存クライアント(建設業)」)を把握してから書く

4. **匿名化方針の適用**(`AI伴走環境/CLAUDE.md`・`日置プロフィール/00_index.md`に明記された既存ルール)
   - 実名(会社名・個人名)は一般化した表現に置き換える
   - 具体的な金額・年収レンジは書かず、相対表現(例:「現状より上振れの余地がある」)にとどめる
   - 地名など個人特定につながる情報も新たに追加しない

5. **新情報の切り分けと反映**
   - ログの内容を切り口ごとに仕分ける目安:
     - 直近の案件・状況の変化 → `02_現在の状況(複業構成).md`
     - 意思決定のルール・交渉の仕方 → `05_意思決定と交渉のスタイル.md`
     - 価値観・自己理解・パーソナリティ → `03_人生目的と価値観.md`
     - つまずき・繰り返しパターン → `04_課題感とつまずきパターン.md`
     - 発信・コミュニケーションの仕方 → `06_コミュニケーション・発信スタイル.md`
     - AIとの協働に関する期待・運用ルールの変化 → `07_AIへの期待(伴走支援に求めること).md`
     - 経歴・スキル・希望条件の変化 → `01_経歴とスキル.md`
   - 既存ファイルの見出し構成に沿って追記する(全面書き換えはしない)。日付入り小見出し(例:`## 2026年8月6日:〜`)を使うと鮮度が追いやすい
   - 反映前に同内容が既に書かれていないか確認し、重複追記を避ける

6. **コミット & プッシュ**
   - 更新したファイルだけを `git add`(`git add -A`は使わない)
   - コミットメッセージには元ログの日付を明記する(例:「音声会話ログ(YYYY-MM-DD)の内容を日置プロフィールに反映」)
   - `git push -u origin <現在のブランチ>`

7. **報告**
   - どのファイルにどんな内容を反映したかを箇条書きでユーザーに要約する
   - 匿名化のために意図的に落とした情報(実名・金額など)があれば一言触れる

## 注意点

- 音声ログの原本(匿名化前)は削除・移動しない。`AI伴走環境/`直下にそのまま残し、匿名化済みの反映先(`日置プロフィール/`)とは別レイヤーとして扱う
- 内容の解釈に迷う場合(パーソナリティ表記など音声認識の精度に不安がある箇所)は、断定せず「音声認識の精度により表記ゆれあり、要本人確認」のような注記を残す
- 匿名化・仕分けの最終判断はそのつどログの内容を読んで行う。過去の反映パターンを機械的にテンプレート適用しすぎない
